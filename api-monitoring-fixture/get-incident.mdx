`GET /v1/incidents/{incident_id}`

Return an incident by ID. See the [Incident object](/api-monitoring-fixture/overview#incident-object) for the response fields.

See [Authentication](/api-monitoring-fixture/authentication) for the API key header.

## Path parameter

| Name | Type | Description |
| --- | --- | --- |
| `incident_id` | string (UUID) | The incident's stable `id`. |

## Responses

- `200`: An `Incident` JSON object, as defined on the shared page.
- `400`: `invalid_incident_id` if the ID is not a UUID.
- `404`: `incident_not_found` if no incident has that ID.

Error responses use the shared `{ "error": { "code", "message" }, "request_id" }` shape. A missing or invalid API key returns `401` before the incident ID is looked up.

## Example response — HTTP 200

```json
{
  "id": "8a65861a-d78e-4330-8763-18e8cb67c190",
  "title": "Checkout latency is elevated",
  "severity": "high",
  "status": "open",
  "reporter": { "id": "usr_42", "display_name": "Taylor" },
  "created_at": "2026-10-06T12:00:00Z",
  "updated_at": "2026-10-06T12:00:00Z",
  "resolved_at": null,
  "resolution": null,
  "metadata": { "service": "checkout" }
}
```
