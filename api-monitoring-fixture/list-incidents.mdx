`GET /v1/incidents`

Return incidents in the current project, newest first. Use filters to narrow the result set and `cursor` to fetch the next page.

See [Authentication](/api-monitoring-fixture/authentication) for the API key header.

## Query parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `status` | `open` \| `acknowledged` \| `resolved` | No | Return only incidents in this state. |
| `severity` | `low` \| `medium` \| `high` \| `critical` | No | Return only incidents of this severity. |
| `service_id` | string | No | Return incidents associated with this service. |
| `assignee_id` | string | No | Return incidents assigned to this responder. |
| `limit` | integer, 1–100 | No | Maximum results; defaults to `25`. |
| `cursor` | string | No | Opaque cursor from a previous response. |

Results are ordered by `created_at` descending. Do not parse or modify cursors. A `400` response with error code `invalid_cursor` means the cursor is invalid or expired.
