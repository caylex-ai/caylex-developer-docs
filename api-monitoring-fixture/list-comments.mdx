`GET /v1/incidents/{incident_id}/comments`

Return comments on an incident in chronological order. Internal comments are visible only to project members with incident access.

See [Authentication](/api-monitoring-fixture/authentication) for the API key header.

## Parameters

| Name | In | Type | Description |
| --- | --- | --- | --- |
| `incident_id` | Path | UUID | ID of the incident. |
| `limit` | Query | integer, 1–100 | Maximum comments to return; defaults to `25`. |
| `cursor` | Query | string | Cursor from the previous response. |

## Response — HTTP 200

```json
{
  "data": [
    {
      "id": "cmt_01J9K7PQ2B",
      "incident_id": "8a65861a-d78e-4330-8763-18e8cb67c190",
      "body": "Investigating the checkout deployment from 11:45 UTC.",
      "visibility": "internal",
      "author": { "id": "usr_17", "display_name": "Morgan" },
      "created_at": "2026-10-06T12:08:00Z"
    }
  ],
  "next_cursor": null
}
```

`404 incident_not_found` means the incident does not exist. `400 invalid_cursor` means the cursor is invalid or expired.
